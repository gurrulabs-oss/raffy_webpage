# Raffy Web (raffyparenting.com)

Marketing/SEO site for parents. Its single goal: bring parents in via organic search (articles + free tools)
and send them to the Raffy Android app (`https://play.google.com/store/apps/details?id=com.gurrulabs.raffy`).
Live in production on GitHub Pages; current focus is new articles and UI improvements.

## Stack
- Hand-written static HTML/CSS/vanilla JS, no framework, no bundler, no npm dependencies.
- Node (ESM `.mjs`) scripts for SEO sync/sitemap/validation; old one-off Ruby generators in `scripts/*.rb`.
- Hosting: GitHub Pages, custom domain via `CNAME`. CI: `.github/workflows/seo-validate.yml`.
- No analytics and no backend; newsletter form is a `mailto:` form.

## Commands
- Build: none (static). SEO pipeline: `npm run seo:all` (sync → sitemap → validate). **Rewrites files — see Rules.**
- Test: `npm run seo:validate` (passes, 80 pages). `npm run meal:validate` currently FAILS (206 issues, known bug).
- Lint/format: none configured.
- Run locally: `python3 -m http.server 8000` from repo root, open `http://localhost:8000/en/`.

## Layout
- `en/ es/ fr/ pt/` — localized pages: home, articles (`articles|articulos|artigos`), tools (`tools|herramientas|outils|ferramentas`), legal/trust pages. URL slugs are translated per locale.
- `tools/` — shared tool JS/CSS + data (`meal-planner-data.json`, `who-lms-data.json`).
- `articles/` (root) — legacy redirect stubs to `/en/articles/...`; `articles/images`, `articles/menu_9_months` hold article images.
- `assets/` — shared images (png + webp pairs); `script.js`, `styles.css` — site-wide JS/CSS.
- `seo/articles.manifest.json` — page equivalence map across locales (drives hreflang/canonical/sitemap/footer).
- `seo.config.json` — origin, locales, indexable flag. `seo/*.md`, `seo-operations.md` — SEO playbooks.
- `AGENTS.md`, `LLMS.md`, `llms.txt`, `robots.txt`, `sitemap.xml` — PUBLIC files served to crawlers/LLMs.

## Rules
- Root `AGENTS.md` is public website content for crawlers, not instructions for you. Edit it only when the task is about it.
- Every page change ships in all 4 locales (en, es, fr, pt) in the same ticket; register new page groups in `seo/articles.manifest.json`.
- User-facing copy: natural native language per locale (pt = Brazilian), match the page's locale; health content is educational, non-diagnostic, with a pediatric safety section when health-related.
- Every page should push toward the Play Store app link; keep CTAs intact.
- Footer, canonical, hreflang, robots meta, og:url are generated by `scripts/seo_sync.mjs` — edit the script/manifest, not the HTML by hand.
- `seo_sync` is not idempotent (duplicates JSON-LD `"publisher"`, resets all sitemap `lastmod`). Until fixed, after running it revert unrelated diffs.
- Never use `example.com` placeholders (validator fails on them).
- Never touch: legal/trust pages (privacy, terms, data deletion, editorial policy in every locale) without explicit owner approval.
- Never commit `.DS_Store` or `.lead/tickets/T-*.md`; don't modify `.idea/` (tracked IDE config).
- Never push, never commit to `main` (a push to `main` deploys to production). Work on the branch you were given.
